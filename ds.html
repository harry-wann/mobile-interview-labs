資料結構:基礎到進階

本章目標:每個資料結構都回答三個問題——長什麼樣?各操作多快?什麼時候用它? 範例以 Java 為主(對應你的課程),並標注 iOS/Swift 的對應型別。章末附面試題組。

0. 先懂複雜度:Big-O

衡量「資料量 n 變大時,時間/空間怎麼長」。只看最高次項、忽略常數。

複雜度 名稱 直覺 例子
O(1) 常數 跟 n 無關 陣列按索引取值、HashMap 查找(平均)
O(log n) 對數 每步砍一半 二分搜尋、平衡樹操作
O(n) 線性 全部看一遍 走訪陣列、鏈結串列查找
O(n log n) 線性對數 好的排序 合併排序、快速排序(平均)
O(n²) 平方 雙層迴圈 氣泡排序、暴力找重複
O(2ⁿ) 指數 爆炸 暴力解費氏數列、子集枚舉

面試表達方式:「這個解法是 O(n²),因為外層迴圈 n 次、內層最多 n 次;用 HashSet 可以把內層查找降到 O(1),整體變 O(n),代價是 O(n) 的額外空間。」——能講出時間換空間的取捨,比背答案重要。

✏️ 熱身:以下程式的時間複雜度?(點擊看解答)
for (int i = 1; i < n; i *= 2) {      // ①
    for (int j = 0; j < n; j++) { }   // ②
}

①每次 i 翻倍,跑 log n 次;②每次跑 n 次 → O(n log n)。

1. 陣列(Array)與動態陣列

索引:  0    1    2    3
      ┌────┬────┬────┬────┐
      │ 10 │ 25 │ 37 │ 42 │   ← 記憶體連續
      └────┴────┴────┴────┘
操作 複雜度 原因
按索引讀寫 a[i] O(1) 位址 = 起點 + i × 元素大小,直接算
尾端新增(動態陣列) 均攤 O(1)(見下) 滿了才擴容(複製到 2 倍大的新陣列)
中間插入/刪除 O(n) 後面全部要搬
搜尋(未排序) O(n) 只能逐個看
搜尋(已排序) O(log n) 二分搜尋

「均攤 O(1)」(amortized O(1))是什麼意思? 大部分的尾端新增就是放進下一格,O(1);偶爾一次「滿了要搬家」是 O(n)(整批複製到更大的新陣列)。但因為每次擴容都是加倍,搬家的頻率越來越低——把那次 O(n) 的成本「分攤」到之前的每次新增上,平均每次還是 O(1)。這就是「均攤」:偶爾貴一次,平均起來便宜。

  • Java:int[] / ArrayList;Swift:Array(本身就是動態陣列)。
  • 使用情境:讀多寫少、需要隨機存取。90% 的「清單」場景就用它:行情列表、聊天訊息。
  • 快取友善:記憶體連續,CPU 快取命中率高——所以即使複雜度相同,陣列實務上常比鏈結串列快。

二分搜尋(必會手寫)

int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // 防溢位寫法(面試加分)
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

2. 鏈結串列(Linked List)

head → ┌────┬───┐   ┌────┬───┐   ┌────┬───┐
       │ 10 │ ●─┼──→│ 25 │ ●─┼──→│ 37 │ ╳ │
       └────┴───┘   └────┴───┘   └────┴───┘
        值   next     (節點分散在記憶體各處)
操作 複雜度
已知節點處插入/刪除 O(1)(改指標就好)
按索引存取 O(n)(只能從頭走)
搜尋 O(n)
  • 使用情境:頻繁在頭尾增刪、不需要隨機存取。例如 LRU 快取(LRU = Least Recently Used,滿了就淘汰「最久沒被用到」的那筆;搭配 HashMap 實作)、作業系統的工作佇列。實務上直接用鏈結串列的機會少,但面試手寫題極多(反轉、找環、合併)。
class ListNode { int val; ListNode next; ListNode(int v) { val = v; } }

// 必背:反轉鏈結串列(迭代版)
ListNode reverse(ListNode head) {
    ListNode prev = null, curr = head;
    while (curr != null) {
        ListNode next = curr.next;  // 先存下一個
        curr.next = prev;           // 反轉指標
        prev = curr;                // 兩個指標往前走
        curr = next;
    }
    return prev;
}
✏️ 經典題:怎麼判斷鏈結串列有沒有「環」?(點擊看解答)

快慢指標(Floyd 判圈):慢指標一次走 1 步、快指標一次走 2 步;有環必相遇,無環快指標先到 null。時間 O(n)、空間 O(1)。

boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;
    }
    return false;
}

另一解:走過的節點丟 HashSet,看過就有環——時間 O(n) 但空間 O(n)。講出兩解與取捨是加分點。

3. 堆疊(Stack)與佇列(Queue)

Stack(LIFO 後進先出)          Queue(FIFO 先進先出)
      │ 30 │ ← push/pop         出 ←─ 10 │ 25 │ 30 ─← 入
      │ 25 │    都在頂端
      │ 10 │
      └────┘
  • Java:兩者都建議用 ArrayDeque(push/pop 當 Stack,offer/poll 當 Queue)。
  • Stack 使用情境:復原(Undo)、瀏覽器上一頁、函式呼叫堆疊、括號配對、運算式求值、DFS(Depth-First Search,深度優先搜尋:一條路走到底再回頭,詳見 §7)。
  • Queue 使用情境:任務排隊、BFS(Breadth-First Search,廣度優先搜尋:一圈一圈往外擴,詳見 §7)、訊息緩衝(行情 tick 先進先出處理)。
  • 變形:雙端佇列 Deque(兩端都能進出)、環形緩衝區(固定容量,行情串流常用)。
// 必背:括號配對
boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    Map<Character, Character> pairs = Map.of(')', '(', ']', '[', '}', '{');
    for (char c : s.toCharArray()) {
        if (pairs.containsValue(c)) stack.push(c);              // 左括號入堆疊
        else if (stack.isEmpty() || stack.pop() != pairs.get(c)) return false;
    }
    return stack.isEmpty();
}

4. 雜湊表(Hash Table)——最重要的一個

key "BTC" ──hash()──→ 雜湊值 ──% 桶數──→ 桶索引 3
                                          │
桶: [0] [1] [2] [3] [4] ...
              ↓
            ("BTC",1650萬) → ("XYZ",42)   ← 碰撞時串成鏈(Java 8+ 過長轉紅黑樹)
操作 平均 最壞
插入/查找/刪除 O(1) O(n)(全部撞同一桶)
  • Java:HashMap / HashSet;Swift:Dictionary / Set。
  • 三個必懂機制(Java 章 3.3 詳述,這裡複習): 1. hashCode 定桶 → equals 比對;兩者必須一起覆寫。 2. 碰撞處理:鏈結法(Java)或開放定址法。 3. 負載因子 0.75 觸發擴容 rehash。
  • 使用情境:只要題目出現「找出現過沒有」「計數」「配對」,第一反應就是雜湊表。它是用 O(n) 空間買 O(1) 查找的標準交易。
// 必背:Two Sum(雜湊表思維的代表題)
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // 值 → 索引
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);     // 需要的「另一半」出現過嗎?
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);
    }
    return new int[0];
}   // O(n) 時間、O(n) 空間;暴力雙迴圈是 O(n²)

5. 樹(Tree)

5.1 二元搜尋樹(BST)

        50              規則:左子樹 < 節點 < 右子樹
       /  \
     30    70           中序走訪(左→根→右)= 由小到大排序
    /  \   /  \
  20   40 60   80
操作 平衡時 退化時(插入已排序資料)
查找/插入/刪除 O(log n) O(n)(變成一條鏈)

退化問題 → 自平衡樹:AVL 樹(嚴格平衡,查多改少)、紅黑樹(近似平衡,改動成本低——Java 的 TreeMap/TreeSet、HashMap 的桶都用它)。面試講到「紅黑樹」通常只要:知道它是自平衡 BST、操作 O(log n)、TreeMap 底層是它,不需要背旋轉細節。

使用情境:需要「排序 + 範圍查詢」。例:掛單簿用 TreeMap<價格, 訂單列表>,隨時取最高買價 lastKey()、找「價格 ≥ x 的所有單」tailMap(x)。這是 HashMap 做不到的。

5.2 走訪(必會)

// 中序走訪(遞迴)—— BST 會得到排序結果
void inorder(TreeNode node) {
    if (node == null) return;
    inorder(node.left);
    visit(node);
    inorder(node.right);
}

// 層序走訪(BFS,用 Queue)
void levelOrder(TreeNode root) {
    Queue<TreeNode> q = new ArrayDeque<>();
    if (root != null) q.offer(root);
    while (!q.isEmpty()) {
        TreeNode n = q.poll();
        visit(n);
        if (n.left != null) q.offer(n.left);
        if (n.right != null) q.offer(n.right);
    }
}

前序=根左右(複製樹)、中序=左根右(BST 排序)、後序=左右根(先處理子再處理根,如刪除)、層序=一層層(最短路徑類)。

5.3 其他樹(知道概念即可)

  • Trie(字典樹):按字元一層層存字串;自動完成、搜尋提示(輸入 "BT" 提示 "BTC")。查找 O(字串長度)。
  • B+ 樹:多路平衡樹,節點大、樹矮,適合磁碟;資料庫索引用它(MySQL InnoDB)。面試連結:「為什麼資料庫索引不用雜湊?因為要支援範圍查詢與排序。」

6. 堆積(Heap)與優先佇列

最小堆積(min-heap):每個節點 ≤ 子節點        用「陣列」存完全二元樹:
        10                                   [10, 25, 15, 40, 30]
       /  \                                  父 i → 子 2i+1, 2i+2
     25    15
    /  \
  40    30
操作 複雜度
取最小(頂) O(1)
插入 / 刪頂 O(log n)
建堆 O(n)

(插入=新元素放在陣列最後,再一路「跟父節點比,比它小就交換」往上換到正確位置,術語叫上浮 sift-up;刪頂=把最後一個元素搬到頂端,再一路往下換,叫下沉 sift-down。每次交換上/下一層,樹高 log n,所以是 O(log n)。)

  • Java:PriorityQueue(預設最小堆積);Swift 無內建,面試時可說「用 Heap 套件或自己實作」。
  • 使用情境:「不斷有新元素進來,每次都要拿最大/最小」。
    • Top-K 問題(必考):從百萬筆成交找金額最大的 10 筆 → 維護大小為 K 的最小堆積,新元素比堆頂大就換掉,O(n log K),不用全排序。
    • 任務排程(最早到期先做)、合併 K 個已排序串流(行情多來源合併)。
// Top-K:金額最大的 k 筆
PriorityQueue<Trade> minHeap = new PriorityQueue<>(Comparator.comparing(Trade::getAmount));
for (Trade t : trades) {
    minHeap.offer(t);
    if (minHeap.size() > k) minHeap.poll();   // 擠掉目前最小的
}
// 堆裡剩下的就是最大的 k 筆

7. 圖(Graph)

鄰接串列表示法:                  A ──── B
A: [B, C]                        │      │
B: [A, D]                        C ──── D
C: [A, D]
D: [B, C]
  • 表示法:鄰接串列 Map<節點, List<鄰居>>(稀疏圖,最常用)vs 鄰接矩陣(稠密圖、查邊 O(1))。
  • BFS(佇列):一圈圈擴散 → 無權圖最短路徑、社交距離。
  • DFS(遞迴/堆疊):一路走到底 → 連通塊、走迷宮、拓撲排序(課程先修關係、建置相依性)。
  • 進階名詞(知道用途即可):Dijkstra(帶權最短路徑)、拓撲排序(有向無環圖排先後)。
// BFS 模板(必背)
void bfs(Map<String, List<String>> graph, String start) {
    Set<String> visited = new HashSet<>();
    Queue<String> q = new ArrayDeque<>();
    q.offer(start); visited.add(start);
    while (!q.isEmpty()) {
        String node = q.poll();
        visit(node);
        for (String next : graph.getOrDefault(node, List.of())) {
            if (visited.add(next)) q.offer(next);   // add 回傳 false = 已看過
        }
    }
}

使用情境:幣種兌換路徑(BTC→ETH→JPY 怎麼換最划算=帶權圖最短路徑)、推薦關係、相依解析。

8. 排序:至少會講這三個

排序 平均 最壞 空間 穩定 一句話
快速排序 O(n log n) O(n²) O(log n) ✗ 選一個基準值(pivot),比它小的放左、大的放右,兩半各自遞迴;最壞=每次都選到最大/最小值,分不成兩半
合併排序 O(n log n) O(n log n) O(n) ✓ 切半、各自排、合併;穩定但要額外空間
堆積排序 O(n log n) O(n log n) O(1) ✗ 建堆後反覆取頂
  • 穩定=相同 key 保持原相對順序(多欄位排序時重要:先按時間排、再按價格排,價格相同時間序不亂)。
  • Java 實際用:物件排序 Timsort(合併排序改良,穩定)、基本型別 雙軸快排。
  • 小抄:Collections.sort(list, Comparator.comparing(Trade::getPrice).thenComparing(Trade::getTime))。

10. 綜合面試題組

✏️ 題 1:設計資料結構,支援 O(1) 的 insert、delete、getRandom(隨機取一個元素)。(點擊看解答)

組合技:動態陣列 + HashMap。 - 陣列存元素(getRandom:隨機索引 O(1))。 - HashMap 存「元素 → 它在陣列的索引」(insert/delete 定位 O(1))。 - delete 的技巧:把要刪的元素和陣列最後一個交換,再刪尾端(避免中間刪除的 O(n) 搬移)。

這題考的是「單一結構不夠時,組合兩個結構各取所長」——LRU 快取(HashMap+雙向鏈結串列)也是同一思想。

✏️ 題 2:即時成交流中,隨時要查「目前中位數價格」。用什麼結構?(點擊看解答)

雙堆積:一個最大堆積存較小的一半,一個最小堆積存較大的一半,維持兩堆大小差 ≤ 1。 - 中位數 = 兩個堆頂(或其平均),查詢 O(1)。 - 每筆新成交插入 O(log n)。 排序陣列每次插入要 O(n) 搬移;單一堆積只能拿最值拿不到中位數——雙堆積正是為這種「串流 + 中位數」設計的。

✏️ 題 3:掛單簿要支援:加掛單、撤單(用訂單 ID)、查最高買價、查「價格 ≥ x 的所有賣單」。設計資料結構。(點擊看解答)

組合: - TreeMap<BigDecimal, Deque<Order>> buyBook(買簿,價格→該價位訂單佇列;同價位先到先成交 = FIFO)。 - 賣簿同理一個 TreeMap。 - HashMap<String, Order> ordersById:撤單 O(1) 定位(Order 內記住自己的價位,從對應 Deque 移除)。 - 最高買價:buyBook.lastKey() O(log n);範圍查詢:sellBook.tailMap(x)。

考點:TreeMap(排序+範圍)與 HashMap(ID 直查)各司其職;以及想到同價位內要保序(FIFO)。

✏️ 題 4:百萬筆歷史成交已按時間排序,找出某個時間區間 [t1, t2] 內的成交筆數,要快。(點擊看解答)

二分搜尋兩次:找 t1 的「第一個 ≥ t1 的位置」(lower bound)與 t2 的「第一個 > t2 的位置」(upper bound),兩索引相減即筆數。O(log n),不用掃描。 Java:Collections.binarySearch 或手寫 lower/upper bound(手寫更保險,面試官常要求)。 考點:「已排序」三個字就是在暗示二分。
